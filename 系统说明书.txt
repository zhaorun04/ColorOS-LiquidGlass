ColorOS-LiquidGlass V1.9.205.288.135｜Bridge 通知状态机一致性与三档 A/B/C 测试

一、目标与边界
- 保留 V288.112 GPU 参考帧、二维折射、模糊、高光、文件夹/Dock 渲染路径。此版本为可恢复实验，默认设置不改变原始通知行为。
- 0 = 原始通知；1 = V288.134 保守抑制（历史对照）；2 = V288.135 状态机修正后的保守抑制。
- 新设置键：liquidglass_kyant_bridge_notify_mode_288135。设置值未配置时，兼容旧键 liquidglass_kyant_bridge_notify_ab_288134。

二、状态机设计（Mode 2）
- latest pending 与 last delivered 分开维护：只有成功排队，才记录待发送状态；Pending 合并会更新为最新候选；在 post runnable 执行时才更新已送达状态。
- 位置或 Bitmap 身份/代次变化放行；稳定状态最多跳过一次，且 24ms 送达心跳后放行。
- GPU 路径不符合安全条件时采用原始通知。
- 本优化不比较所有动态 Shader 输入，因此 Mode 2 仅用于短时 A/B，验证画面贴合、解锁/回弹、调节参数后再考虑生产使用。

三、日志与统计口径
KYANT288135_HOST：显示 mode、gpu、carrier、frameSync。
KYANT288135_WINDOW（仅 Mode 2）：eligible、queued、merged、suppressed、unsupported、delivered、gateOff、passMoved、passReference、passHeartbeat、passInitial、partition、pending、bridgeVersion。
- 每个 eligible 回调的决策恰好属于 queued/merged/suppressed 中一个，partition 是三者之和，用于自检（不包含 gateOff）。
- passMoved/passReference/passHeartbeat/passInitial 是互斥的候选放行理由；不等于成功排队次数。delivered 是另行发生的 post 回调计数。
- 所有计数是应用层通知事件，不代表 GPU Pass/实际显示帧。

四、Termux 一键测试
在包含 lg_test.sh 的目录运行：
sh lg_test.sh baseline single
sh lg_test.sh optimized single
sh lg_test.sh baseline single
sh lg_test.sh conservative single
也可将 single 改为 multi。脚本设置 GPU 参考帧，关闭历史缓存和裁剪实验，重启 Launcher，重置 gfxinfo，录制 15 秒 Perfetto 并保存日志/设备状态/帧统计。
结果保存于 /sdcard/Download/LG135_TestResults/。录制期间请人工按照相同方式滑动。
关键：优先对比 A→C→A，保持页面与热状态尽可能相同；对比纹理标记密度、RenderThread Drawing 分位和 gfxinfo Janky Frames。异常画质立即停止 B/C。

五、恢复安全配置
su -c 'settings put global liquidglass_kyant_bridge_notify_mode_288135 0; settings put global liquidglass_kyant_bridge_notify_ab_288134 0; am force-stop com.android.launcher'
