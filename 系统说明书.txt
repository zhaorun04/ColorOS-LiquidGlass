ColorOS-LiquidGlass V1.9.205.288.139｜回弹整帧与壁纸采样回调关联诊断版

一、问题与目的
用户观察：不翻页向右滑动松手回弹时，桌面图标和文件夹会同时出现轻微卡顿；玻璃壁纸纹理相对外部壁纸的贴合可把卡顿或不同步显著放大。两类原因可叠加：1）Launcher 整帧延迟；2）Kyant Source 绘制采用的采样位置与当前文件夹的位置更新不一致。V139 仅关联记录这些回调输入，不修改折射、模糊、高光、壁纸 Bitmap、Shader 或 Host 创建逻辑。默认关闭诊断。

二、改动（V138 稳定完整玻璃 A 档基础）
1. 新增独立开关 Settings.Global：liquidglass_kyant_same_frame_probe_288139，0 默认关闭，1 开启诊断。
2. KYANT288139_RELEASE：松手（ACTION_UP 或 CANCEL）事件的单调时间戳和序号。Perfetto 附加瞬间标记 LG139_RELEASE_UP/CANCEL（依赖设备 Trace 类别是否启用）。
3. KYANT288139_PREDRAW：回弹后的 UI PreDraw 原生位置（nativeX/Y）、当时已提交 Compose 状态（committedX/Y）、pendingGapPx、回调间隔和序号。
4. KYANT288139_SOURCE：相同松手序号下，Compose Source Draw 的 drawX/Y、committedX/Y、最近一次 PreDraw 的位置/序号/年龄、实时原生位置、reference generation 和 GPU 参考帧选项。
5. 单个 Host、单次松手窗口 650ms；PreDraw 和 Source 各不超过 9 条日志且至少间隔 45ms。只在已选 Host 记录，非每帧持续打印。仅日志观察仍会有小额开销，先按相同设置复测。
6. versionName=1.9.205.288.139、versionCode=1920529145。
7. 更新 lg_test.sh：仅备份并调整 V139 探针开关与 V138 Host 隔离开关。测试强制 Host 隔离=0（完整 Kyant），结束按原备份恢复。其它光学、GPU、壁纸、调试设置不改动。保存 Perfetto、gfxinfo、Logcat、CPU 频率和 ThermalService 前后快照。

三、关键解释限制
- 同一个 release 序号加回调时刻，不意味着记录均属于同一 SurfaceFlinger 最终呈现帧；PreDraw/Source 也不具有相同的系统 FrameTimeline token。
- 两坐标要先判断坐标系/矩阵一致才能将差值解释为壁纸视觉贴合误差。pendingGapPx/nativeDrawGapPx 仅是回调观察的像素差，不是经像素识别验证的纹理错位。
- Perfetto 命令录制 gfx/view/sched/freq；若设备没有 FrameTimeline datasource，不能宣称已记录或完成 GPU 呈现级归因。
- gfxinfo reset 与 Perfetto 启停是近似窗口，不保证完全同一时段；结合 release 标记和真实 trace 范围解释。
- 诊断 key 需要重新启动 Launcher 才能生效。要确保 Vector 已勾选 com.android.launcher 作用域。
