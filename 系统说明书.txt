ColorOS-LiquidGlass V1.9.205.288.110｜共享参考帧 GPU 直接采样 A/B 实验版

稳定基线：V1.9.205.288.107.3；本版是在 V288.109 性能定位版上实现的独立 A/B 优化。

目标：减少 Native Bridge 在多文件夹滑动时每帧执行的 CPU Canvas(Bitmap) 重采样。沿用 ColorOS 屏幕参考帧、实时浮点坐标、Kyant 原版 layerBackdrop、drawBackdrop 光学效果、模糊、折射、柔和高光和 Dock 设置。没有修改壁纸源文件/同步、设置 UI→SharedPreferences→Root→Launcher 正式配置映射。

A/B 开关（需要重启 com.android.launcher 或通过正常方式重新挂载 Host 才生效）：
  su -c 'settings put global liquidglass_kyant_gpu_reference_ab_288110 0'  # 默认，原有 CPU Bridge
  su -c 'settings put global liquidglass_kyant_gpu_reference_ab_288110 1'  # 实验，GPU 参考帧直接绘制

实验路径：Native View 仍触发 Compose 绘制通知，但停止重采样专属 Bridge Bitmap。Compose 背景绘制阶段直接以硬件加速 Canvas.drawBitmap(reference, null, destination) 绘制共享全屏参考 Bitmap；Kyant 后续 layerBackdrop 光学链不变。
注意：此路径是硬件 Canvas 纹理采样 A/B，不等于严格零拷贝/零纹理上传；GPU 时间、图层缓存、壁纸同步仍需实测。若没有硬件加速 Canvas 或来源位图已回收，临时回退旧 Bridge。

保护条件：仅对原本的 native carrier+Kyant 桥接路径开放，不对多缓冲、仿射、帧冻结、额外 Bitmap 实验、native 独立引擎等模式改写生产数据。每个 Host 创建时会通过 Logcat 写 KYANT288110_HOST requested/effective，首次和低频绘制通过 KYANT288110_DRAW 写是否真正使用硬件 Canvas。如 effective=false，本版不会变更绘制。

性能定位（可选；关闭后无每阶段原子计数）：
  su -c 'settings put global liquidglass_kyant_perf_profile_288109 1'
Logcat 搜索：KYANT288109_PERF 或 KYANT288110_（通过 logcat -b all）。新版汇总附 gpu110Draws/gpu110Hw/gpu110Fallbacks/gpu110NativeSkips。

严谨比较：相同壁纸、文件夹数量及测试手势；先测试默认 CPU 模式并重置 gfxinfo，再测试 GPU 开关=1并重启 Launcher。两个模式都分别保存 FrameStats 和 Perf。要求 GPU 实验下仍有完整模糊、折射、高光；壁纸换新、反向滑动、右边缘、松手回弹位置必须正确。若玻璃不可见/纹理错位或掉帧反而恶化，立刻切回 0 并重启 Launcher。

验证状态：仅完成源码静态改动与 ZIP 完整性检查。未在此环境完成 Android Gradle 编译及真机功能/性能测试。是否对其启用正式优化以真机 A/B 为准。
