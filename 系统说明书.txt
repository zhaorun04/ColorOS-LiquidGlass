ColorOS-LiquidGlass V1.9.205.288.137｜Kyant 内层裁剪来源与设备帧稳定性归因版

目标：解释 V288.136.1 实测“单文件夹 A1/A2 相同配置但 CPU/GPU P90 相差很大”的原因，并区分外层 Modifier.clip 与 Kyant Backdrop 内层 GraphicsLayer 的形状裁剪及离屏合成。

基线：V1.9.205.288.136.1。默认光学渲染与 V288.136.1 A 档相同，不修改折射、模糊、高光、Dock、原生壁纸源或采样坐标。保留旧实验但测试脚本强制关闭其影响。

新增全局设置：liquidglass_kyant_clip_provenance_probe_288137，默认 0。为 1 时，在 Host 初始化记录 KYANT288137_HOST，并于内层 Backdrop GraphicsLayer 录制路径每隔约 3 秒输出 KYANT288137_CLIP。字段包含 layerId、录制尺寸、记录与绘制计数、形状 Outline 修订代次变化、尺寸变化、padding、Effect 是否存在，以及该模块固定的 innerClip=true/offscreenCompositing=true 属性。它不能直接观测 HWUI Vulkan 内部纹理 ID、真实裁剪 Pass 次数或 GPU 帧耗时。

源码裁剪来源清单：
1. 文件夹外层：liquidglass-module/src/main/java/top/liquidglass/vector/KyantLauncherLens270.kt 中 Modifier.clip(RoundedCornerShape(cornerDp))；V288.136 B 档隔离实验未证明显著收益。
2. Kyant Backdrop 内层：backdrop/src/commonMain/kotlin/com/kyant/backdrop/DrawBackdropModifier.kt 的 layoutLayerBlock 中 clip=true, shape=shapeProvider.shape, compositingStrategy=Offscreen；V137 新日志在此节点记录状态。
3. Dock：liquidglass-module/src/main/java/top/liquidglass/vector/KyantDockLens28827.kt 包含 Android View clipToOutline=true 及 Compose RoundedCornerShape clip，Dock 仍保持不变。
4. HookEntry.java 中存在多处原生 Canvas clipPath/clipRect，不应仅从源码出现位置判断它们全部在当前 GPU 渲染通道生效。

Termux：安装新版 APK 后，解压本 ZIP 中的 lg_test.sh 到 ~/ColorOS-LiquidGlass-V1.0-Source，运行：
cd ~/ColorOS-LiquidGlass-V1.0-Source
sh lg_test.sh single a1
sh lg_test.sh single a2
sh lg_test.sh multi m1
sh lg_test.sh pack
sh lg_test.sh restore

单次采集时间约 15 秒，开始前清空日志、重置 gfxinfo，收集 Perfetto、gfxinfo、Logcat、前后 CPU 频率/热状态/内存快照、设置值及采集起止时间。结果保存在 /sdcard/Download/LG137_TestResults/，打包到 /sdcard/Download/LG137_TestResults.tar.gz。采集期间手动在指定页面连续滑动，单文件夹 a1/a2 要保持相同操作。注意 gfxinfo 与 Perfetto 不能保证严格逐帧同步，应以 Perfetto 实际区间为主对照。

边界与安全：V137 不会禁用内层裁剪，不修改 GraphicsLayer 合成策略，也不将调试日志计数视为 GPU 工作量。测试结束恢复设置键 0。新增键与原有 UI→SP→Root→Launcher→Shader 光学设置映射完全独立。

验证状态：Shell 静态语法及 ZIP 完整性检查；Android Gradle/Kotlin 构建和真机实验尚未完成。
