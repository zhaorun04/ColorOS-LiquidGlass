ColorOS-LiquidGlass V1.9.205.288.138｜Launcher 回弹整帧卡顿定位版

一、目标
用户已明确指出，滑动不翻页并松手回弹时，整个 Launcher 桌面、图标和文件夹同时出现不连贯，玻璃内部纹理抖动可能是整帧掉帧放大后的视觉表现。本版先研究整体帧呈现，并不更换光学 Shader、壁纸 Bitmap/坐标、模糊或高光算法。

二、技术修改
1. 新增 Settings.Global：liquidglass_kyant_rebound_host_ab_288138
   0（默认）：完全沿用 V288.137 原 Kyant 文件夹 Host 初始化路径，渲染效果不变。
   1（仅测试）：在 KyantLauncherLens270.run() 入口跳过创建文件夹 Kyant 光学 Host，保留 OEM FolderIcon / Workspace 原有图标和动画，并继续安装轻量 TouchRelease 时间标记 Hook。该实验仅隔离通过此入口创建的 Kyant 文件夹 Host；Dock、其他旧路径/模块渲染不保证全部关闭，因此不可称为“全模块玻璃关闭”。
2. 松手 ACTION_UP/CANCEL 标记：KYANT288138_RELEASE + Trace.beginSection("LG138_RELEASE_UP")，用于和系统 gfx/RenderThread 跟踪尝试按单调时钟对齐。Touch Hook 本身有少量开销，A/B 路径均保留。
3. 将模块 versionName 更新为 1.9.205.288.138，versionCode 更新为 1920529144。
4. 更新 lg_test.sh。只修改本次实验所需的两个 Global Settings，首次修改前保存它们的原始值；restore 根据备份恢复原值，原本未设置则删除键，不再重置其它 GPU/渲染/Shader 相关配置。脚本采集 15 秒 Perfetto、gfxinfo、CPU 频率、ThermalService、Logcat 和实际档位。

三、严格测试要求
先确认 Vector 作用域已启用 com.android.launcher，V288.138 安装成功且 A 档玻璃外观正常；固定屏幕刷新率/壁纸/桌面页面，做多次“不翻页回弹”操作。
运行：
 cd ~/ColorOS-LiquidGlass-V1.0-Source
 sh lg_test.sh a single a1
 sh lg_test.sh b single b1
 sh lg_test.sh a single a2
 sh lg_test.sh pack
结果：/sdcard/Download/LG138_TestResults.tar.gz
完成后：sh lg_test.sh restore

四、如何解释结果
单次采集内按 LG138_RELEASE_UP 标记前后约 300～500ms 对齐分析异常帧（若系统 Perfetto 配置包含必要 FrameTimeline 则进一步结合；不能假定缺失的 FrameTimeline 已采集）。比对 A1、B、A2 的 gfxinfo、RenderThread Drawing、CPU/调频状态和画面主观反馈。B 档文件夹玻璃会消失，这是实验设计，不是最终用户体验；如果 B 档变快，仅证明该 Kyant Host 及其连带开销可能参与了问题，不能单凭 A/B 认定具体瓶颈。
脚本的 gfxinfo reset 和 Perfetto 启停不保证纳秒级严格相同，应以可验证的独立时间线对齐为准。Perfetto 中 Trace 标记能否实际显示，取决于设备上的 tracing 配置与相关应用 trace 标签。

五、风险与还原
不要清除 Launcher 数据。B 档仅用于短时诊断，测试结束必须运行 restore。原始 Settings 备份位于 LG138_TestResults/original_settings.tsv，恢复后重命名为 .restored.*.tsv 以供审计。切换实验档时需要重启 Launcher，因此需要重新确认 Vector 注入及文件夹页面。
若出现 B 档没有 HOST_DISABLED、两档玻璃均不见、或者松手标记完全缺失，停止采集并排查，而不是据此判定优化有效。
